# Immich – מדריך התקנה והפעלה בעברית

חבילת התקנה מוכנה ל‑**Immich** (גרסה `v3`) – תחליף Self‑Hosted ל‑Google Photos שרץ על השרת שלך,
מגבה אוטומטית מהאייפון, מזהה פרצופים ומקטלג את כל הספרייה.

> **חשוב:** הקבצים כאן הם קובצי ההתקנה הרשמיים שהורדו מ‑
> `github.com/immich-app/immich/releases/latest`. את ההתקנה עצמה יש להריץ **על השרת שלך** –
> אני לא יכול להתקין מרחוק על מכונה שאין לי גישה אליה.

## 1. מה Immich יודע לעשות

| יכולת | פירוט |
|---|---|
| **גיבוי אוטומטי מהנייד** | אפליקציות iOS ו‑Android מעלות ברקע כל תמונה/סרטון חדש. תומך HEIC, Live Photos, RAW, וידאו |
| **זיהוי פרצופים** | מודל ML מקומי מזהה פרצופים, מקבץ אותם לאנשים, ואתה נותן שם. חיפוש לפי אדם |
| **חיפוש חכם (CLIP)** | חיפוש בשפה חופשית: "כלב על החוף", "עוגת יום הולדת" – בלי שהוספת תגיות |
| **קטלוג אוטומטי** | ציר זמן לפי תאריך, מפה לפי GPS, "זיכרונות" (לפני שנה היום), אלבומים, מועדפים |
| **מטא‑דאטה** | קורא EXIF: דגם מצלמה, עדשה, מיקום, תאריך – והכול ניתן לחיפוש |
| **ריבוי משתמשים** | חשבון לכל בן משפחה, אלבומים משותפים, שיתוף בקישור, מצב "שותף" |
| **איתור כפילויות** | מנוע כפילויות + זיהוי תמונות דומות |
| **סל מיחזור** | מחיקה רכה ל‑30 יום |
| **פינוי מקום בטלפון** | "Free Up Space" מוחק מהנייד רק מה שכבר גובה בהצלחה בשרת |
| **ספריות חיצוניות** | לקטלג תיקיות תמונות קיימות **במקום שהן נמצאות**, בלי להעתיק |
| **CLI** | העלאה המונית של ארכיון קיים מהמחשב |

הכול רץ **מקומית** אצלך – שום תמונה לא נשלחת לענן, כולל עיבוד ה‑AI.

## 2. דרישות מהשרת

- **מערכת הפעלה:** לינוקס 64‑ביט (Ubuntu / Debian וכו'). Windows/macOS אפשריים אך לא מומלצים.
- **זיכרון:** מינימום **6GB RAM**, מומלץ **8GB**. עם 4GB בלבד – צריך לכבות את מנוע ה‑ML.
- **מעבד:** מינימום 2 ליבות, מומלץ 4. תמיכה ב‑`amd64` ו‑`arm64`
  (ב‑`amd64` נדרש מעבד ברמת `x86-64-v2` – כלומר כמעט כל מעבד מ‑2012 והלאה).
- **דיסק:**
  - התמונות – כל דיסק/NAS גדול שתרצה.
  - **מסד הנתונים חייב להיות על דיסק מקומי, רצוי SSD.** לא NFS, לא SMB, לא כונן רשת – זה ישבור אותו.
  - הוסף כ‑**10–20%** מעל גודל הספרייה עבור תמונות ממוזערות וּוידאו מקודד.
- **תוכנה:** Docker Engine + התוסף `docker compose` (הפקודה `docker-compose` הישנה לא נתמכת).

התקנת Docker באובונטו:

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # ואז להתנתק ולהתחבר מחדש
```

## 3. התקנה – שלב אחר שלב

```bash
# 1. העתק את תיקיית immich/ הזו לשרת, למשל ל-/srv/immich
sudo mkdir -p /srv/immich && cd /srv/immich

# 2. הרץ את ההתקנה, ותן לה את הנתיב שבו יישמרו התמונות
./install.sh /srv/immich/library
```

הסקריפט: בודק ש‑Docker קיים ותקין, מזהיר אם אין מספיק RAM, יוצר `.env` עם **סיסמת מסד נתונים
אקראית**, מוודא שמסד הנתונים לא יושב על כונן רשת, מוריד את הקונטיינרים ומעלה את השירות.

התקנה ידנית (אם אתה מעדיף):

```bash
cp .env.example .env
nano .env            # קבע UPLOAD_LOCATION ו-DB_PASSWORD
docker compose up -d
```

**אחרי ההפעלה:**

1. פתח בדפדפן `http://<כתובת-השרת>:2283`
2. במסך הראשון – צור את **משתמש האדמין** (זו הפעולה הראשונה, אין סיסמת ברירת מחדל).
3. `Administration → Users` – פתח חשבון לכל בן משפחה.
4. `Administration → Settings` – שם נמצאות כל ההגדרות שנדבר עליהן בהמשך.

מה עלה בפועל: 4 קונטיינרים – `immich_server` (השרת והממשק),
`immich_machine_learning` (זיהוי פרצופים וחיפוש חכם), `immich_postgres` (מסד נתונים),
`immich_redis` (תורי משימות).

## 4. הגדרת האייפון – גיבוי אוטומטי

1. התקן את **Immich** מה‑App Store.
2. במסך הכניסה הזן את כתובת השרת: `http://<כתובת-השרת>:2283` והתחבר עם המשתמש שיצרת.
3. לחץ על אייקון הענן בפינה הימנית העליונה → מסך הגיבוי.
4. בחר אילו אלבומים לגבות (למשל "Recents" – הכול). הקשה כפולה על אלבום = **החרגה**.
5. גלול למטה ולחץ **Enable Backup**.

**הגדרות קריטיות ב‑iOS:**

- ✅ הפעל **Background App Refresh**: `הגדרות → כללי → רענון אפליקציות ברקע`.
  בלי זה הגיבוי ירוץ רק כשהאפליקציה פתוחה.
- iOS מחליט בעצמו מתי להריץ משימות רקע – ככל שתפתח את האפליקציה יותר, כך היא תרוץ יותר.
- ברירת המחדל: העלאה **רק ב‑Wi‑Fi**. אפשר לשנות בהגדרות הגיבוי.
- **Album Sync** – יוצר בשרת אלבומים בשמות זהים לאלבומים שבטלפון (סנכרון חד‑כיווני).
- **Free Up Space** – מוחק מהטלפון רק קבצים שכבר גובו בשרת בהצלחה.

> ⚠️ **אזהרה חשובה למשתמשי iCloud Photos:**
> iCloud מסנכרן **דו‑כיווני**. מחיקת תמונה מהאייפון (כולל דרך Free Up Space) תמחק אותה גם מ‑iCloud
> ומכל המכשירים שלך. אם iCloud הוא הגיבוי המשני שלך – אל תשתמש ב‑Free Up Space, אלא ב‑
> "Optimize iPhone Storage" של אפל. תמונות מ‑Shared Albums של iCloud מוחרגות אוטומטית.

**מיגרציה מ‑Google Photos:** הורד את הארכיון דרך Google Takeout, ואז מהמחשב:

```bash
npm install -g @immich/cli
immich login http://<שרת>:2283 <API-KEY>   # מפתח: Account Settings → API Keys
immich upload --recursive /path/to/takeout
```

## 5. גישה מחוץ לבית (בבטחה)

**אל תפתח את פורט 2283 לאינטרנט ישירות.**

| שיטה | מתי מתאים |
|---|---|
| **Tailscale / WireGuard** (VPN) | הכי פשוט ובטוח למשפחה. מתקינים על השרת ועל האייפון, ומזינים באפליקציה את כתובת ה‑VPN |
| **Reverse Proxy + HTTPS** | Caddy/Nginx + Let's Encrypt על דומיין משלך – כשרוצים לשתף קישורים החוצה |
| **Immich Cloudflare Tunnel** | ללא פתיחת פורטים בראוטר |

דוגמת Caddy (שורה אחת נותנת HTTPS אוטומטי):

```
photos.example.com {
    reverse_proxy localhost:2283
}
```

## 6. זיהוי פרצופים

### איך זה עובד

שירות ה‑ML מריץ שני מודלים: **זיהוי פרצוף** (איפה יש פנים בתמונה) ואז **הטבעת פרצוף**
(וקטור מספרי שמייצג את הפנים). לאחר מכן אלגוריתם קיבוץ מבוסס **DBSCAN** מקבץ פרצופים דומים ל"אדם".
פרצוף הופך ל"נקודת ליבה" רק אם יש סביבו מספיק פרצופים דומים – כך נמנעות קבוצות שגויות.

### הפעלה ותפעול

- זיהוי הפרצופים פועל **אוטומטית** על כל תמונה חדשה. בהתקנה ראשונה זה לוקח זמן – ספרייה של
  50,000 תמונות יכולה לקחת שעות עד יממה על CPU.
- מעקב: `Administration → Job Queues` – שם המשימות **Face Detection** ו‑**Facial Recognition**.
- התוצאות: לשונית **Explore** → רשימת האנשים. לוחצים על אדם → נותנים שם → מעכשיו הוא ניתן לחיפוש.

פעולות שימושיות על אדם: שינוי תמונת הנושא, הסתרה מהתצוגה, **מיזוג שני אנשים** (אותו אדם שזוהה
פעמיים), קביעת **תאריך לידה** (ואז מוצג הגיל בכל תמונה), וסימון כמועדף.

### כוונון – `Administration → Settings → Machine Learning Settings → Facial Recognition`

| הגדרה | מה עושה | המלצה |
|---|---|---|
| **Facial recognition model** | מודל הזיהוי | ברירת המחדל היא הטובה ביותר. בשרת חלש – בחר מודל קטן יותר |
| **Minimum detection score** | מאיזה ביטחון נחשב "פרצוף" | **אל תרד מתחת ל‑0.5**. גם 0.9 גרוע – יפספס פרצופים רבים |
| **Maximum recognition distance** | כמה שני פרצופים צריכים להיות דומים כדי להיחשב אותו אדם | ברירת מחדל טובה. בבית עם תאומים – הורד מעט. **טווח בטוח: 0.3–0.7** |
| **Minimum recognized faces** | כמה פרצופים דרושים כדי ליצור "אדם" חדש | ברירת מחדל 3. הגדלה = פחות רעש. 1 = כל פרצוף יוצר אדם (עבודה ידנית רבה) |

**טיפים:**
- שינוי `Minimum detection score` חל רק על תמונות חדשות – כדי להחיל על הכול צריך להריץ מחדש
  **Face Detection → All**.
- אם העלית את הספרייה בהדרגה, הקיבוץ עלול לצאת פחות טוב. עדיף להריץ פעם אחת
  **Facial Recognition → All** אחרי שכל התמונות בפנים – זה מקבץ הכול מאפס ונותן תוצאה טובה יותר.
- אם כבר נתת שמות ולא רוצה לאבד אותם: תייג ידנית כמה פרצופים לא‑משויכים והרץ
  **Facial Recognition → Missing**.
- מרחק זיהוי גבוה מדי = בלגן שקשה לתקן. מרחק נמוך מדי = רק צריך למזג אנשים כפולים. **עדיף נמוך מדי.**

## 7. קטלוג, חיפוש וארגון קבצים

### חיפוש חכם
`Administration → Settings → Machine Learning → Smart Search`. מנוע CLIP מייצר וקטור לכל תמונה
ומאפשר חיפוש חופשי בשפה טבעית. אפשר להחליף למודל גדול יותר (מדויק יותר, כבד יותר) או למודל
רב‑לשוני שמבין גם עברית. אחרי החלפת מודל – הרץ **Smart Search → All**.

### תבנית האחסון (Storage Template)
קובעת איך הקבצים נשמרים פיזית בדיסק. `Administration → Settings → Storage Template`.

ברירת המחדל:
```
{{y}}/{{y}}-{{MM}}-{{dd}}/{{filename}}.{{ext}}
```

דוגמאות:
```
{{y}}/{{MM}}/{{filename}}                                  →  2026/09/IMG_1234.HEIC
{{y}}/{{#if album}}{{album}}{{else}}Other{{/if}}/{{MM}}/{{filename}}
```

אחרי שינוי התבנית יש להריץ את המשימה **Storage Template Migration** כדי להחיל אותה על הקיים.
כך הספרייה נשארת קריאה גם בלי Immich – פשוט תיקיות לפי שנה/חודש.

### ספריות חיצוניות (External Libraries)
לקטלוג תמונות שכבר קיימות בשרת/NAS, **בלי להעתיק אותן**:

1. הוסף mount ל‑`docker-compose.yml`:
   ```yaml
   immich-server:
     volumes:
       - ${UPLOAD_LOCATION}:/data
       - /mnt/nas/old-photos:/mnt/media/old-photos:ro   # ro = לקריאה בלבד, Immich לא ימחק
   ```
2. `docker compose up -d`
3. `Administration → External Libraries → Create Library` → הוסף את הנתיב **כפי שהקונטיינר רואה
   אותו** (`/mnt/media/old-photos`, לא `/mnt/nas/...`) → **Scan**.
4. תבניות החרגה (glob): `**/Raw/**`, `**/*.tif`, `**/\@eaDir/**` (חשוב ב‑Synology).

סריקה מחדש רצה כמשימת לילה; אפשר גם "Scan all libraries" ידנית.

### עוד כלים לקטלוג
- **Duplicates** – מציאת כפילויות ומחיקה מרוכזת.
- **Map** – כל התמונות על מפה לפי GPS.
- **Memories** – "לפני שנה היום", אוטומטי.
- **XMP Sidecars** – תגיות מתוכנות עריכה חיצוניות.

## 8. איך מגדילים את נפח האחסון

### א. להצביע על דיסק גדול יותר (הדרך הנכונה)

כל התמונות יושבות תחת `UPLOAD_LOCATION`. כדי לעבור לדיסק גדול:

```bash
cd /srv/immich
docker compose down                          # 1. עצור
rsync -aH /srv/immich/library/ /mnt/bigdisk/immich/   # 2. העתק (שים לב ל-/ בסוף)
nano .env                                    # 3. UPLOAD_LOCATION=/mnt/bigdisk/immich
docker compose up -d                         # 4. הפעל
```

⚠️ **את `DB_DATA_LOCATION` משאירים על ה‑SSD המקומי** – מסד הנתונים לא עובד על כונן רשת.

### ב. NAS / כונן רשת
אפשרי עבור התמונות בלבד. עגון אותו במערכת (`/etc/fstab`) והצבע עליו את `UPLOAD_LOCATION`.
עבור NFS מומלץ `hard,intr`. אם ביצועי הדיסק איטיים (HDD), בטל את ההערה מהשורה
`DB_STORAGE_TYPE: 'HDD'` ב‑`docker-compose.yml`.

### ג. ספרייה חיצונית במקום העתקה
אם יש לך כבר 2TB תמונות ב‑NAS – **אל תעתיק אותן**. חבר אותן כ‑External Library (סעיף 7).
Immich יקטלג אותן במקומן, ותחסוך את כפל הנפח.

### ד. הרחבה פיזית של הדיסק
- **LVM** – `lvextend -l +100%FREE /dev/vg/lv && resize2fs /dev/vg/lv` להוספת דיסק לנפח קיים.
- **mergerfs** – מאחד כמה דיסקים לתיקייה לוגית אחת (פופולרי מאוד עם Immich).
- **ZFS / btrfs** – הוספת vdev, snapshots וגיבוי מובנה.
- **RAID** – יתירות מפני תקלת דיסק (אבל RAID אינו גיבוי!).

### ה. מכסות למשתמשים
`Administration → Users → Edit → Quota` – מגבילים כמה GB כל בן משפחה יכול לתפוס.

### ו. לחסוך מקום קיים
| פעולה | חיסכון |
|---|---|
| `Settings → Video Transcoding` – קידוד ל‑H.265/HEVC, הגבלת רזולוציה ל‑1080p | הכי משמעותי, סרטונים תופסים הכי הרבה |
| `Settings → Image Thumbnails` – הורדת איכות התמונות הממוזערות | 5–10% |
| **Duplicates** – מחיקת כפילויות | תלוי בספרייה |
| ריקון סל המיחזור (`Settings → Trash`, ברירת מחדל 30 יום) | מיידי |
| מחיקת גיבויי DB ישנים (`Settings → Backup`, ברירת מחדל 14) | קטן |

בדיקת הצריכה בפועל:
```bash
du -sh /srv/immich/library/*
docker exec immich_server df -h /data
```

## 9. גיבוי ושחזור

**Immich הוא לא גיבוי בפני עצמו.** דיסק שנשרף לוקח איתו הכול. עבוד לפי כלל **3‑2‑1**:
3 עותקים, 2 מדיות שונות, 1 מחוץ לבית.

**מה חייבים לגבות:**
1. **מסד הנתונים** – Immich יוצר dump אוטומטי מדי יום ב‑02:00 לתוך `UPLOAD_LOCATION/backups`
   (שומר 14 אחרונים; ניתן לשינוי ב‑`Administration → Settings → Backup`).
   מסד הנתונים מכיל את כל המטא‑דאטה: שמות אנשים, אלבומים, תיאורים – **בלעדיו התיקיות חסרות משמעות**.
2. **תיקיית `UPLOAD_LOCATION`** כולה – התמונות עצמן + התיקייה `backups`.

הסקריפט המצורף עושה את שניהם:

```bash
./backup.sh /mnt/backup-drive/immich
```

והוספה ל‑cron לגיבוי לילי:
```
0 4 * * * /srv/immich/backup.sh /mnt/backup-drive/immich >> /var/log/immich-backup.log 2>&1
```

**שחזור:** `Administration → Maintenance → Restore database backup`, או בהתקנה חדשה –
מעתיקים את התיקיות (`library`, `upload`, `thumbs`, `encoded-video`, `profile`, `backups`)
ל‑`UPLOAD_LOCATION` החדש ובוחרים **Restore from backup** במסך הפתיחה.

## 11. האצת חומרה (GPU)

יש בתיקייה שני קבצים מוכנים. בטל את ההערה מהקטע המתאים ב‑`docker-compose.yml`:

```yaml
immich-machine-learning:
  extends:
    file: hwaccel.ml.yml
    service: cuda        # או: openvino / rocm / armnn / rknn

immich-server:
  extends:
    file: hwaccel.transcoding.yml
    service: nvenc       # או: quicksync / vaapi / rkmpp
```

בנוסף, ל‑ML יש להוסיף סיומת ל‑tag של האימג':
`ghcr.io/immich-app/immich-machine-learning:${IMMICH_VERSION:-release}-cuda`

זה מאיץ דרמטית את זיהוי הפרצופים והחיפוש החכם. אינטל עם iGPU → `quicksync`/`openvino`,
NVIDIA → `nvenc`/`cuda`, AMD → `vaapi`/`rocm`.

## 12. פתרון תקלות

| בעיה | פתרון |
|---|---|
| הקונטיינר של ה‑ML קורס / נהרג | חוסר RAM. הוסף swap, או כבה `Settings → Machine Learning → Enabled` |
| הגיבוי מהאייפון לא רץ ברקע | הפעל Background App Refresh; פתח את האפליקציה מדי פעם – iOS מלמד את עצמו |
| ספרייה חיצונית לא נסרקת | הנתיב חייב להיות **כפי שהקונטיינר רואה אותו**. בדוק: `docker exec -it immich_server ls /mnt/media/...` |
| שגיאת `ENOSPC` בצפייה בקבצים | `sudo sysctl fs.inotify.max_user_watches=524288` |
| Postgres לא עולה | `DB_DATA_LOCATION` על NFS/SMB/NTFS. העבר לדיסק מקומי |
| ממשק איטי בספרייה גדולה | ודא שה‑DB על SSD; הפעל האצת חומרה |
| שינויים בקבצים לא מופיעים | Immich לא סורק את הדיסק לבד – הרץ Scan מדף הספריות |

**פקודות שימושיות:**
```bash
docker compose ps                          # מצב השירותים
docker compose logs -f immich-server       # לוגים
docker compose restart                     # הפעלה מחדש
docker compose down                        # עצירה (הנתונים נשמרים)
```
